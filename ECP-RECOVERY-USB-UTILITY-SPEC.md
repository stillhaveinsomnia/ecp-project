# ECP Recovery USB Utility — Спецификация для разработки

## Описание проекта

Необходимо разработать **отдельное десктопное приложение** (кроссплатформенное: Windows, macOS, Linux), которое позволяет:
1. **Записать** зашифрованный файл восстановления ECP на USB-флешку.
2. **Прочитать** файл восстановления с USB-флешки и отобразить его статус.

Приложение работает **в связке** с мобильным приложением ECP (p2p-ECP). Мобильное приложение генерирует **Recovery Key** (256-bit ключ) и зашифрованный **Recovery Blob** (файл `.ecp-recovery`). Десктопная утилита записывает этот блоб на флешку.

---

## Контекст: Как работает Recovery Key в ECP

### Формат Recovery Key
- 256-bit (32 байта) случайный ключ.
- Отображается пользователю как **64 hex-символа**, разделённых дефисами на группы по 8: `A1B2C3D4-E5F6G7H8-...`
- Пользователь **записывает его на бумагу** или запоминает. Это единственный способ расшифровать бекап.

### Формат Recovery Blob (файл `.ecp-recovery`)
JSON-файл следующей структуры:
```json
{
  "version": 1,
  "salt": "<hex, 32 chars>",
  "nonce": "<hex, 24 chars>", 
  "ciphertext": "<hex, variable length>"
}
```

- `salt` — 16 байт, используется в HKDF-SHA256 для деривации AES-ключа из Recovery Key.
- `nonce` — 12 байт, IV для AES-256-GCM.
- `ciphertext` — зашифрованный JSON со всем состоянием приложения (контакты, сообщения, криптографические ключи Ed25519/X25519).

### Криптографический стек (для справки, если потребуется верификация)
- **KDF:** HKDF-SHA256(ikm=recoveryKey, salt=blob.salt, info="ECP-RECOVERY-KEY-v1", length=32)
- **Шифрование:** AES-256-GCM(key=derived, nonce=blob.nonce, plaintext=JSON)
- **Библиотеки в мобильном приложении:** `@noble/hashes`, `@noble/curves`, Web Crypto API (`crypto.subtle`)

## Функциональные требования к десктопной утилите

### 1. Запись на USB (Write Mode)

**Входные данные:**
- Пользователь выбирает файл `.ecp-recovery` с компьютера (или перетаскивает drag-and-drop).
- Пользователь выбирает USB-флешку из списка подключённых устройств.

**Действие:**
- Копирует файл `.ecp-recovery` в корневую директорию USB-флешки.
- Опционально: создаёт файл `README.txt` рядом с бекапом с инструкциями по восстановлению.

**Верификация:**
- После записи читает файл обратно и сравнивает хеш (SHA-256) с оригиналом.
- Отображает статус: "✅ Backup verified on USB" или "❌ Verification failed".

### 2. Чтение с USB (Read Mode)

**Входные данные:**
- Пользователь подключает USB-флешку.
- Утилита автоматически ищет файлы `*.ecp-recovery` на всех подключённых USB-устройствах.

**Действие:**
- Отображает найденные файлы, их размер и дату создания.
- **НЕ расшифровывает** (для расшифровки нужен Recovery Key, который вводится только в мобильном приложении).
- Показывает метаданные: `version`, размер `ciphertext`.

### 3. Передача на телефон (Transfer Mode)

**Опция A: QR-код**
- Если файл небольшой (< 2 КБ), утилита может отобразить QR-код с содержимым блоба.
- Мобильное приложение ECP сканирует QR и расшифровывает.

**Опция B: Локальный HTTP-сервер**
- Утилита поднимает локальный HTTP-сервер на случайном порту.
- Отображает QR-код с URL: `http://192.168.x.x:PORT/recovery`.
- Мобильное приложение сканирует QR, скачивает файл по локальной сети, расшифровывает.

## Технические требования

### Рекомендуемый стек
- **Electron** или **Tauri** (Tauri предпочтительнее из-за меньшего размера бинарника и нативного Rust-бекенда).
- **UI:** Минималистичный интерфейс. Одно окно, 3 вкладки (Write / Read / Transfer).
- **Определение USB:** 
  - Windows: WMI / `wmic logicaldisk` 
  - macOS: `diskutil list`
  - Linux: `/dev/disk/by-id/usb-*` или `lsblk`

### Безопасность
- Утилита **не имеет доступа к Recovery Key**. Она работает только с зашифрованным блобом.
- Не хранит никаких данных на компьютере после закрытия.
- Не требует интернет-соединения (полностью оффлайн).

### Формат файла на USB
```
USB_ROOT/
├── ecp-backup-2026-09-23.ecp-recovery    # Зашифрованный блоб
└── ECP-README.txt                          # Инструкция
```

Содержимое `ECP-README.txt`:
```
ECP Recovery Backup
===================
This USB drive contains an encrypted backup of your ECP messenger data.

To restore:
1. Open the ECP app on your new device.
2. Select "Restore from Recovery Key".
3. Connect this USB drive or use the ECP Recovery Utility to transfer.
4. Enter your Recovery Key (the 64-character code you wrote down).

WARNING: Without the Recovery Key, this file CANNOT be decrypted.
The Recovery Key is NOT stored anywhere — only you have it.
```

## Связь с основным проектом

Исходный код мобильного приложения ECP: `d:\Workspace\ECProtocol\p2p-ECP`

Ключевые файлы для понимания формата данных:
- `components/cryptography/recoveryKey.ts` — генерация ключа, шифрование/дешифрование блоба
- `components/cryptography/e2ee.ts` — криптографический стек (Ed25519, X25519, AES-GCM, HKDF)
- `components/storage/AppStorage.ts` — формат `AppStoredData` (то, что шифруется)
- `components/storage/storageSchema.ts` — схема настроек устройства

## Критерии приёмки

1. ✅ Утилита запускается на Windows, macOS, Linux без установки (portable binary).
2. ✅ Корректно определяет подключённые USB-устройства.
3. ✅ Записывает `.ecp-recovery` файл на USB с верификацией SHA-256.
4. ✅ Читает и отображает метаданные файлов `.ecp-recovery` с USB.
5. ✅ Поднимает локальный HTTP-сервер для передачи файла на телефон.
